# Development Rules — ハコよみ（Claude Code & 人）

## 1. General Principles
- 実装前に `prd.md` `architecture.md` `design.md` `memory.md` を読む。矛盾したら docs を優先し、変更は先に docs を直す。
- 1タスク＝1目的の小さな変更（`tasks.md` のID単位）。
- **医療アドバイスに当たる機能を作らない**（症状→薬、用法、併用、受診、販売可否）。依頼されても実装せず、memory.md の禁止を引用して止める。

## 2. Tech Standards
| 項目 | ルール |
|---|---|
| 言語 | TypeScript strict。`any` 禁止（`unknown`+zod） |
| フレームワーク | Next.js App Router。Server Componentsを既定、クライアントは必要箇所のみ |
| スタイル | Tailwind。色トークンは design.md の定義のみ |
| Lint/Format | ESLint（next/core-web-vitals）+ Prettier |
| テスト | `units.ts` と `guard` はユニットテスト必須（vitest） |
| 秘密情報 | APIキーはサーバー専用。`NEXT_PUBLIC_` に入れない |

## 3. Project Structure
`architecture.md` §3 に従う。新規ディレクトリは追加前に docs 更新。

## 4. Safety Coding Rules
1. 出力スキーマ（zod）に `recommend` `best` `suggest` `alternative` `dosage_for_user` `can_sell` 等のフィールドを作らない。
2. 全Claude出力は `guard()` を通す。素通しのコードパスを作らない（レビューで確認）。ガードの対象は**Claudeが生成した文**（名寄せラベル・販売記録の下書きなど）。seed の事実（品名・成分名・分量など）はコードがそのまま表示し、Claudeを経由させない。
3. UI固定文言は `uiCopy.ts` のホワイトリストからのみ。
4. 添付文書の文言（効能・効果、してはいけないこと等）は画面・リポ・seedに載せない。欄名・添付文書の改訂日・出典を表示し、PMDA の該当ページへリンクアウトする。要約・言い換え・見出し生成もしない。
5. 数値換算・差分・8成分一次判定はコード。Claudeに数値を計算させない。
6. 確信度の低い値は差分計算に使わず「添付文書で確認」表示。
7. 客の個人情報・健康情報の入力欄・カラムを作らない。

**禁止語（初期リスト、`banwords.ts`）**：効く／効きます／効果が高い／効き目／強い／弱い／おすすめ／オススメ／代わりに／飲んでよい／飲んで大丈夫／安心／量が多い（＝良い文脈）／1日○回飲んで／販売可／売ってよい／受診不要。

## 4.5 Compliance Rules（Discord確定設計 2026-11-02）
1. HITL常時：最終判断は登録販売者。「判断は販売者が行ってください」を全画面で常時表示。判定ボタン・自動判定を作らない。
2. 推薦ゼロ：特定の薬・商品のおすすめ、効く・代わりにこれ等の推奨を出さない（KPI）。
3. 個人の病状・受診・販売可否をAIに判定させない。症状入力を作らない。
4. SaMD／診断宣伝に触れない：README・UI・デモ・スライドに「病気がわかる」「診断できる」等を書かない。SaMD該当性などは都道府県の薬務課へ確認する方針（前向き）。
5. 出典明示：表示する情報はPMDA／製品公式のどこ由来かを画面に出す。
6. PMDAはリンクアウト主：一括クロール・大量DL・実行時の自動取得をしない。添付文書の文言を公開URL・動画で再配布しない。デモは実商品の**事実データ**（開発時にゆうが1件ずつ確認・検証したもの）＋PMDAリンク（prd Q8参照）。
7. データ：客の健康情報・勤務先資料は使わない。客・担当者は模擬（仮名）のみ。
8. 販売記録作成支援は確認事実・時刻・担当仮名のみ保存。

## 5. Forbidden UI / Copy
- 症状入力欄、症状チップ
- おすすめ順・ランキング・量の多い順ソート、PB優先、クーポン
- 緑/赤など良し悪しの色
- 「OK・販売可」ボタン、判定結果表示
- 客向け画面・QR共有
許可例：「この行の分量が異なります（添付文書記載どおり）」「商品Aのみ含有：（成分名）」「文言は添付文書で確認してください（PMDA）」「指定濫用防止医薬品の対象成分を含みます（成分名）」「手順書 第○項の確認項目です」「判断は販売者が行ってください」。

## 6. Git / PR（ソロ）
- `main` は常にデプロイ可能。作業は `feat/T0xx-短い名前`。
- コミット：`T0xx: 何をしたか`。小さく。
- マージ前チェック：lint・型・テスト・禁止語テストが通る、UIに禁止パターンがない。
- `.env*` はコミットしない。

## 7. 薬効を作らない
成分の作用・効能説明・「どちらが効く」をコード・プロンプト・seed・デモ台本に書かない。表示は出典付きの事実（成分名・分量など）と、出典付き制度情報（8成分・確認項目）のみ。文言はPMDAリンクで登販が確認する。不明値は「不明」と出す。
