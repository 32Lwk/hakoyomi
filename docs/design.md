# Design — ハコよみ

改訂 2026-11-02（L-20261102-28）：JAN主経路に全面改訂。箱写真の撮影・PhotoZoom（bbox拡大）・製品画像は廃止。添付文書の文言は画面に出さずPMDAへリンク。

## 1. Audience & Context
- 登録販売者。明るい店内、レジ横、片手、列待ち。客には画面を見せず登販が口で伝える。
- 起点は**客が手に持つ商品（箱）のJAN**（症状ではない）。JAN読取（@zxing/browser）＋手入力常設＋品名検索。
- 商品は実商品・実名表示。表示するのは開発時に検証した事実データのみ。

## 2. Layout（単一縦画面）
```
┌ ヘッダ：ハコよみ | 判断は販売者が行ってください（常時）
├ 上段：商品A／商品B の特定結果（品名・メーカー・リスク区分・出典）
├ 中段：2商品の違い（基準揃え表。違う行だけ強調）
│       添付文書の確認先アコーディオン（効能・効果／してはいけないこと …） A｜B
├ 下段：指定濫用防止 帯（対象/非対象・根拠成分・個数→複数）
│       確認項目チェック（手順書順）→［確認を記録］→ 販売記録下書き
│       棚カード（棚番・段）
└ 下端固定：［商品AのJANを読む］［商品BのJANを読む］［JAN入力／品名検索］ 個数 −/+
```
- スマホで差と確認項目までスクロール最小。PCは2カラム（左：JAN入力・商品特定、右：結果）。
- JAN読取はカメラのプレビューのみ。フレームは保存・送信しない（デコードした数字だけ使う）。

## 3. Color
- ベースは白/濃グレー文字。**強調は「違う」の1色のみ**（例：琥珀 `#F5B700` 背景薄）。
- 緑/赤の良し悪し色は使わない。濫用帯は中立色（濃紺枠）。
- 不確実値：グレー＋「添付文書で確認」。

## 4. Typography & Interaction
- 数値は大きく（スマホ 20px以上）、行高タップ領域44px以上。
- 値タップ→その値の出典（添付文書の欄名・改訂日・PMDAリンク）を展開。画像の拡大表示はしない。
- アコーディオン：閉＝欄名＋添付文書改訂日。開＝出典＋PMDA該当ページへのリンク＋「文言は添付文書で確認してください」。文言・要約・見出し生成は出さない。
- JAN読取ボタンは下端、1タップ。読取失敗時はその場で手入力欄にフォーカス。

## 5. States
| 状態 | 表示 |
|---|---|
| 空 | 「商品AとBのJANを読み取るか、入力してください」 |
| 読取中 | カメラプレビュー＋「JANを枠に合わせてください」。手入力リンクを常時表示 |
| 照合中 | スケルトン＋商品ごとの進捗（A/B並列）。区分判定が出たら先に帯を表示 |
| 未登録JAN | 「このJANはデモデータにありません。品名検索／JANを入力し直す」 |
| 不確実 | グレー＋「添付文書で確認」＋PMDAリンク＋JAN読み直しリンク |
| ガード差し止め | 「表示できない文言が含まれたため省略しました」 |
| エラー | 「読み取れませんでした。もう一度読む／JANを入力する」 |
| 記録完了 | 「確認済み 21:41」（判定表現なし） |

## 6. Responsive
スマホ主、PCデモ副。どちらも同一URL。PCはJAN手入力・品名検索を主に使う。

## 7. Tone
業務的・事実のみ。ウェルネス調・励まし・絵文字なし。「判断は販売者が行ってください」を常時表示。症状入力はどこにもない。

## 8. Source Labels
- 表示する値にはすべて出典（例：「PMDA 添付文書 成分・分量欄（改訂 20XX-XX）」＋リンク）。
- 担当者名・手順書・棚は模擬であることを画面上で明示。

## 9. Demo配慮
差の行を量順に並べ替えない。実名は表示する（Q2 クローズ）が、比較画面で特定商品を良く／悪く見せる表現・配色はしない。
