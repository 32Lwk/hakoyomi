## 1. Product Overview
**一言定義：** 登録販売者の説明の質を揃える。ベテランと新人の差をなくし、誰が対応しても同じ根拠で客に伝えられるようにする。

**これではない：** 推薦ツール／一般購入者向けアプリ／販売可否判定ツール

**どう揃えるか（§5と同一方針）：** 箱面の全文OCRを主にしない。レジ横で**JANコードをカメラで読み取り**（必要なら手入力・品名検索）、そのJANの実商品について、開発時にPMDAの添付文書から抽出・検証済みの**事実**（成分名・分量・基準量・リスク区分・内容量など）を引く。2商品の差分、指定濫用防止の確認材料、文言の確認先（PMDAリンク）、**自店棚番（肝）**までを、登販が同じ根拠で話せる材料として出す。判断・選定・客への説明は登販が行う。（改訂 L-20261102-28）

## 2. Problem Statement
1. **答えが人によって違う**：「これとこれ、何が違うの？」への答えが「箱を客と同じく読む」か「その人の知識」次第。箱は表記基準がばらばら（「1日量中」vs「3錠中」）で、レジ前でそのまま比べられない。
2. **人手不足と同時対応の負荷**：ドラッグストアの登販求人は倍率が高い（求人倍率3倍超の報道・求人実態）。列とレジが同時に動く中で、教育・引き継ぎの時間が足りず、ベテランと新人で説明の根拠が揃わない。ここは「未経験者が法的に一人で店を回す」という意味ではなく、**人手不足のもとでの同時対応と、知識のばらつきがそのまま接客品質のばらつきになる**ことが痛い。
3. **指定濫用防止の確認漏れ（いちばん痛い瞬間）**：2026-05-01施行改正で、かぜ薬・せき止め等の成分が「指定濫用防止医薬品」に入り、現場ではその場で「対象か／小容量か大容量か／何を確認するか」を判断しきれない抜けが出る。典型は、夜の忙しい時間帯に若い客が同じせき止めを2箱持ってくる場面——列ができ、すぐ隣に聞ける先輩がいない。厚労省の覆面調査では、濫用のおそれがある薬の複数購入への対応が「適切」だった店は86.8%（令和7年度）で、約13%に抜けがある（R6 88.4%から低下）。**あなたにしかない深さ：** 書き手自身がドラッグストアで登録販売者として売り場に立ち、この抜けと説明のばらつきを体感している。机上の仮説ではなく、現場の仕事の不便そのもの。**本来誰にでも届くべきもの：** 購入者＝全国民は、一般用医薬品について同等の正しい知識・情報を得るべきだが、現場の課題感のせいで正しい知識が平等に届いていない。全員に伝わるべきなのに、伝えられていない。Built with Claude Japan 2026 の公式出発点である「あなたが一番よく知っていること」「日々の仕事の不便」（および人手不足など日本社会の課題）に、この現場痛は直接乗る。出典：registered_seller_job_pain_research.md §1／hakoyomi_research_competitors_20261101.md §公式ページ（審査基準は未公開、出発点のみ記載）。

## 3. Goals / Non-goals
§1の一言定義と§2の現場痛から導く。機能リストではなく、何が揃えば成功かを書く。

**Goals**
- G1：**説明の根拠を揃える** — 誰が対応しても、次の3つの同じ材料で客に伝えられる状態にする（§1）。
  1. **JAN由来の数値：** JANで引く実商品の成分名・分量（基準量を揃えた値）・内容量・リスク区分など、比較・確認に使う定量・区分情報。開発時にPMDAの添付文書から抽出し、ゆうが検証したもの（出典・添付文書改訂日つき）。
  2. **原文の確認先：** 効能・効果、「してはいけないこと」などの文言は画面に出さず、欄名・添付文書改訂日・出典とともにPMDAの該当ページへリンクする（Q8。要約・言い換え・見出し生成なし）。登販が自分で原文を確認する。
  3. **手順書の確認項目：** 指定濫用防止医薬品について、対象か／小容量か大容量か／今回何を確認するか、を自店（MVPは模擬）手順書の順で並べた確認リスト。
- G2：**人による答えのばらつきを減らす** — 「何が違うの？」に対し、知識頼みではなく箱表示を揃えた差として示せる（§2-1）。
- G3：**人手不足下でも確認が抜けにくい** — 列とレジが同時でも、指定濫用防止の「対象か／容量／今聞く項目」が手順書順で手元に出る（§2-2・§2-3）。
- G4：**正しい情報が購入者に届く前提を作る** — 推奨ではなく、登販が伝える材料を平等に揃える。全国民が同等の正しい情報を得るべきなのに、現場の抜けで届いていない状態を縮める（§2「本来誰にでも届くべきもの」）。
- G5：**現場知をプロダクトにする** — 登録販売者として体感した深さ（あなたにしかない深さ）を、推薦なしの業務支援として実装し、BWCの「一番よく知っていること／日々の仕事の不便」に応える（§2）。
- G6：**推薦ゼロを守る** — 医療アドバイス・おすすめ・販売可否判定を出さない。判断は登販のまま。

**Non-goals**
- 症状起点の提案、効き目比較、用法の個人計算、併用・受診・販売可否の判定
- 一般購入者向けアプリ化（画面は登販向け。伝えるのは人）
- POS・在庫発注連携、認証・多店舗運用（ハッカソン期間外）
- MedNavi・道場・試験対策としての再フレーミング

## 5. Core Features（MVP Must）と受け入れ基準
方針：**箱の画像認識で全文OCRするのが主ではない**。カメラで**JANコード**を拾い、そのJANの実商品の検証済み事実データを引く。添付文書の文言は画面に出さずPMDAへリンクする。製品画像は取得・保管しない。

| # | 機能 | 受け入れ基準 |
|---|---|---|
| M1 | JAN読取による商品特定と事実表示 | カメラ（@zxing/browser、手入力・品名検索を常設）でJANを読み取り、デモSKUの事実データ（品名・メーカー・リスク区分・成分名・分量・基準量・内容量）を返す。事実データは開発時に、ゆうがPMDAの添付文書を1件ずつ開き、ローカルでClaudeに抽出させ、ゆうが検証してseed化（一括DL・実行時の自動取得なし。文書ファイル・文言はリポに入れない）。各項目に出典（添付文書の欄・改訂日・PMDA URL）。検証できなかった値は `uncertain=true`。箱面OCRは補助に留め、主経路にしない |
| M2 | 基準を揃えた差分表示 | 換算はコード関数。名寄せはClaude（実行時）。違う行だけ1色で強調。並べ替えで量の多寡を強調しない。値タップで出典（欄名・改訂日・PMDAリンク）を表示 |
| M3 | 原文の確認先アコーディオン | 効能・効果、「してはいけないこと」などを欄ごとに折りたたみ。閉じた状態は欄名と添付文書改訂日、開くと出典とPMDA該当ページへのリンク＋「文言は添付文書で確認してください」。文言の表示・要約・見出し生成はしない（Q8） |
| M4 | 指定濫用防止の対象表示＋個数 | 2026-05改正で重要。8成分（告示第32号）との照合結果を根拠成分つきで表示。生薬主体の製剤は seed の印で対象外とし根拠（通知 1(2)）を表示。小容量／大容量は開発時にゆうが告示第33号の基準（5日／7日）で判定した値と根拠を表示。購入個数入力で「複数個」該当を表示。A/Bが同じ指定成分を含む場合は「両方の購入は複数個に該当（医薬発1226第16号 第4-1(5)）」と事実のみ表示（販売可否の判定はしない） |
| M5 | 手順書チェック＋記録 | MVPで必須度は中（「なくても回るが、改正で確認が厳しくなっているので書けると強い」）。模擬手順書の確認項目は通知（医薬発1226第16号 第4-1(4)）のア〜キをその順で使い、項目ごとに出典を表示。「18歳未満なら氏名」は確認した事実のみ記録し氏名は保存しない。タップで確認済み。判定ボタンなし。保存は項目・時刻・担当（仮名）のみ。客の氏名・回答詳細は保存しない |
| M6 | 禁止語・因果表現ガード | 全Claude出力（名寄せラベル・販売記録下書き等の生成文）をルール（正規表現）＋Claude自己検査で通し、検出時は該当出力を差し止めてログ。seedの事実はコードが表示しClaudeを経由しない。**UI文言はホワイトリスト** |
| M8 | 販売記録作成支援 | Discord確定設計（2026-11-02）で明記。M5の確認事実をもとに販売記録の下書きを作る。保存は商品・個数・確認項目・時刻・担当（仮名）のみ。客の氏名・健康情報・回答詳細は保存しない。判定ボタンなし |
| M7 | 自店棚番表示（プロダクトの肝） | JAN、または客から聞いた品名・情報で商品を特定し情報を並記したあと、**登販（専門家）が「こちらで説明する／こちらを案内する」と決めた商品**について「それはどこ？」と聞かれたときに、自店の棚番・段を即答できる。架空1店舗マップ【仮】。**アプリが薬を推薦する機能ではない**（判断・選定は登販） |

## 6. User Stories
接客の一本線（定義ドキュメントの21:40場面をJAN主経路に更新）：列待ちのレジ横で、客がかぜ薬を2つ持って「何が違うの？」「2個ほしい」「それはどこ？」と続く。登販はJAN（または品名検索）→添付文書・製品情報取得→構造化→差分→アコーディオン原文→濫用確認→棚番、の順で材料を揃える。言うのは登販。

- **US1 JAN比較（差と確認先）**：登販として、客の手にある2商品（または客が言った品名）について、**JANを読み取るか品名検索**し、成分・分量の違いを15秒で見たい。差分は基準揃え。文言を確かめたいときはアコーディオンからPMDAの添付文書を開ける。客には「違いはここ。添付文書ではこの欄」と自分の言葉で伝えられるように。
- **US2 濫用確認＋記録**：登販として、2個購入の客に対し、対象かどうかと根拠成分、手順書順の確認項目を見て聞き漏らしを防ぎ、確認した事実を記録したい。判断は自分がする（判定ボタンなし）。
- **US3 棚（肝）**：登販として、比較・説明のあと**自分が案内すると決めた商品**について客から「それはどこ？」と聞かれたら、自店の棚番・段を即答したい。アプリに推薦はさせない。
- **US5 販売記録**：登販として、確認した事実から販売記録の下書きを作り、自分で確認して残したい。客の健康情報は残さない。
- **US4 JAN解決の不確実**：登販として、JANが読めない／デモデータに無い／検証できていない値があるときは灰色＋「添付文書で確認」とJAN読み直し・手入力・品名検索の導線で示してほしい。誤った数値で比較したくない。

## 7. Success Metrics
**必須KPI：推薦ゼロ**（全出力を禁止語リスト＋人手で検査し、推薦・効能の因果・用法指示が0件）

| 指標（デモ用） | 目標 |
|---|---|
| JAN由来の添付文書・製品情報と、抽出した成分・分量・区分が一致する割合（デモ10組） | 測定して提示（高いほど良い。目標値【仮】95%） |
| JAN撮影（または品名検索）→差分表示までの秒数 | 15秒以内 |
| 指定濫用防止の対象判定と8成分リストの一致 | 10組全件一致 |
| Claudeなし版（JANマスタ単独）との比較 | マスタに無い／構造化が必要な商品で差が出ることを示し、Claudeあり版の必然を説明する |
| 原文の確認先 | 効能・「してはいけないこと」などの欄ごとに改訂日・出典・PMDAリンクが出て、文言・要約が画面に出ていないことをデモ10組で確認 |
| 棚番即答 | 登販が選んだ商品について、自店棚番・段が即表示される（架空1店舗マップでデモ） |
| 不確実時のグレー表示 | JAN読取失敗・未登録JAN・未検証値を灰色＋「添付文書で確認」／JAN読み直し／手入力導線で示す（意図的に壊したケースで確認） |

現場用（デモ後・未測定）：手順書確認項目の完遂率、回答開始までの秒数、新人／ベテランの根拠一致率。

## 8. Constraints / Compliance
- **BWC禁止例「医療アドバイスを行うAI」**：Discord回答取得（2026-11-02 JST）。
  - Kai（Cerebral Valley）：HITL原則がないものが禁止事例。一般用医薬品を扱うこと自体ではなく、事実確認が難しい・人間を除いて責任追及できないサービスが問題。該当しなければルール上OK。
  - 岡本（小児科医アドバイザー）注意6点（法的助言ではない）：①AIに個人の病気を判断させない ②「病気がわかる」「診断できる」と説明・宣伝しない ③薬や商品を推さない ④最終判断は資格のある人（Claude利用規約上も医療判断を直接返すなら資格者が先に確認しAI使用を明示）⑤健康情報は慎重に。実在の客情報は使わず作例で、勤務先資料は許可なく使わない ⑥根拠（出典）と困ったときの行き先（医療機関等への一般案内）を示す。医療関連は設計を書いて #質問 で運営確認。
  - 照合：ハコよみは症状→薬なし・診断なし・推薦ゼロ・登販が常に最終判断・客の健康PII不保持・PMDA/添付文書の出典表示・禁止語ガードで全項目に整合 → **ルール上OK**。ルール範囲の一般回答であり**個別作品の承認ではない**。Won'tは厚く維持。
- **Discord確定設計（2026-11-02 JST、#質問へ設計共有の返信投稿済み。作品名義の正式承認ではない）**
  - 想定ユーザー：ドラッグストアの登録販売者（お客様向けではない）
  - やること：JAN読取／品名検索→公開の添付文書・製品情報を構造化・差分表示（原文引用）／指定濫用防止の確認項目を手順書順に提示し確認事実の記録支援／販売記録作成支援／自店棚番表示／画面に出典明示／最終判断は常に登録販売者（HITL）、「判断は販売者が行ってください」常時表示（※「原文引用」は L-20261102-28 で「文言はPMDAへリンクアウト」に変更）
  - やらないこと：症状入力、個人の病状・受診・販売可否のAI判定／特定の薬・商品のおすすめ／効く・代わりにこれ等の推奨／客の健康情報・勤務先の無断データ利用（模擬データのみ）
  - データ取得：PMDAおよび各製品の公式サイトを情報源（取得方法の制約はQ8：リンクアウト主・一括クロールなし・全文を公開再配布しない）
  - 医療機器該当・宣伝文言に触れない。SaMD該当性などは都道府県の薬務課にも確認する方針
- **薬機法上の判断は登販**：アプリは材料を揃えるだけ。販売可否判定はしない（Q&A問2）。
- 個人健康情報・客の顔・身分証は扱わない。学習に使わない。
- 認証なし（ハッカソン期間）。公開URLの商品データは実商品の事実のみ（文言なし）。客・担当者・手順書・棚は模擬。
