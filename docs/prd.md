## 1. 開発目的（正本）
ドラッグストアは誰もが日常的に使う場所で、そこで医薬品の説明をするのは登録販売者である。登録販売者の説明には体系的に決まった型がなく、属人的である。新人はベテランの背中を見て育ち、説明の仕方や内容は現場で学んでいく。

一方で、お客様にとって新人かベテランかは関係ない。**誰もが受けられるべき同じ水準の説明が、時間帯や接客する人によって変わってしまう**。これが現場の大きなペインであり、ハコよみはこれを解決するためのプロダクトである。

ハコよみは、**JANコードを読み取るだけで、これまで箱の細かい文字にしかなかった医薬品の情報を手元の端末に出す**。お客様から「この薬とこの薬の違いは？」「眠くなる成分は入ってる？」「スポーツをしているけど大丈夫な成分？」「○○のときに使える薬はどれ？」と聞かれたとき、差分をすぐに示し、公的な根拠から正確に答えを引き、バッジで一目で分かるように見せる。これにより新人とベテランの知識の差をなくし、お客様への説明を**正確に・的確に・速く**行えるよう支援する。

**最終判断と説明は常に登録販売者が行う（HITL）。** ハコよみは根拠をそろえる道具であり、薬を推薦しない。

## 2. Problem Statement
1. **説明の水準が人と時間帯で変わる**：「何が違うの？」「眠くならない？」への答えが、その場にいる人の知識と経験しだい。新人は根拠を探すのに時間がかかり、ベテランの説明の型は言語化されずに残らない。
2. **箱の情報は読みにくく、比べにくい**：成分表は小さく、分量の基準表記も商品ごとに違う（「1日量中」「3錠中」）。レジ前で何品も見比べるのは難しい。
3. **人手不足と同時対応**：列とレジが同時に動き、隣に聞ける先輩がいない時間帯がある。教育の時間も足りない。
4. **2026年5月の指定濫用防止医薬品の制度開始**：確認・記録の負担が増えた。厚労省の覆面調査では、濫用のおそれのある薬の複数購入への対応が適切だった店は86.8%（令和7年度）。
5. **本来誰にでも届くべきもの**：一般用医薬品の正しい情報は、全員に同じ水準で届くべき。現場の属人性のせいで届き方に差が出ている。

BWC テーマ1「あなたにしかない深さ」（ベテランの仕事を次の人が受け継げる形に）とテーマ2「本来、誰にでも届くべきもの」の両方に乗る。書き手自身が売り場に立つ登録販売者である。

## 3. Goals / Non-goals
**Goals**
- G1：**説明の水準をそろえる** — 新人でもベテランと同じ根拠で、同じ速さで答えられる。
- G2：**速い** — JAN読取から情報・バッジ表示まで数秒。質問への回答も十数秒以内。
- G3：**正確で、根拠が見える** — すべての表示と回答に出典（公的通知の該当箇所・商品の事実データ・禁止表の年版）を付ける。出典のない回答は出さない。
- G4：**ベテランの説明を受け継げる** — 説明のポイントを店内で共有し、新人が引ける。
- G5：**推薦しない・判断は人** — おすすめ・順位付け・販売可否の判定をしない。「判断は販売者が行ってください」を常時表示。

**Non-goals**
- 一般購入者向けアプリ（画面は登録販売者向け。お客様に伝えるのは人）
- 個人の病状・受診要否・販売可否のAI判定、用法用量の個人計算
- POS・在庫発注連携、認証・多店舗運用（ハッカソン期間外）

## 5. データと権利の方針（失格条件「権利を有しないデータ」への対応）
参加者ガイドの「権利を有しないコード・データ・素材を使用するものは失格」と、PMDA 規約（添付文書は製造販売業者の著作物で、所属薬局等での内部利用を除き無断の複製・転載を禁止）に合わせ、次の3層で構成する。

| 層 | 中身 | 出どころ | 権利の扱い |
|---|---|---|---|
| ① 商品の事実 | 実商品の品名・メーカー・JAN・リスク区分・薬効分類・成分名・分量・基準量・内容量 | ゆうが箱と PMDA の添付文書を見て、会期中に手で入力・検証 | 事実情報で著作物ではない。商品名は特定のための表示に限る |
| ② 公的な文面 | 「使用上の注意」の記載事項と記載条件（36薬効群＋指定濫用防止）、製造販売承認基準の効能・効果の範囲 | 厚生労働省の通知（下記） | 国の通知（通達）は著作権法13条2号により権利の目的とならない【出典URLと取得日を記録】 |
| ③ 制度・照合用リスト | 指定濫用防止医薬品の8成分と数量基準、WADA禁止表の成分 | 厚労省告示・通知、JADA 公開の禁止表（年版） | 成分名の照合のみ。禁止表の本文は複製せず、JADA・Global DRO へリンク |

- **商品固有の文面（各社の添付文書の本文）は、画面・DB・リポ・動画に載せない。** 該当欄は PMDA のページへリンクアウトする。
- ②は「この商品の成分から導いた、通知上の記載事項」として表示し、「実際の添付文書は PMDA で確認」と必ず併記する（実物と一致しない可能性があるため）。
- 実行時に PMDA へ自動アクセスしない。一括ダウンロード・クロールをしない。
- `data/medicine_data_assets/` は**使わない**（既存プロジェクトの再利用と権利不明データを避ける）。
- お客様の情報は扱わない。逆引き・質問の入力は保存しない。担当者・手順書・店舗・棚は模擬。

**②の一次資料（2026-11-02 取得）**
- 「かぜ薬等の添付文書等に記載する使用上の注意について」（厚生労働省、195ページ。Ⅰ 承認基準のある16薬効群、Ⅱ 承認基準のない20薬効群、Ⅲ 指定濫用防止医薬品）https://www.mhlw.go.jp/content/001742612.pdf
  - 各項目に「〔○○を含有する製剤に記載すること〕」という成分ごとの記載条件がある。これを構造化ルールにして商品の成分に当てはめる。
- 改正履歴：薬食安発1014第4号・薬食審査発1014第5号（平成23年）→ 薬食安発0401第2号・薬食審査発0401第9号（平成27年）→ 薬生薬審発0117第4号・薬生安発0117第3号（令和5年）
- 製造販売承認基準（例：かぜ薬 薬食発0325第28号、平成27年。以後の改正を含む）— 効能・効果の範囲と成分の配合範囲。逆引きに使う【T-R2 で薬効群ごとに出典を確定】

## 6. Core Features と受け入れ基準

### P0（11/8 の提出までに必ず入れる）
| # | 機能 | 受け入れ基準 |
|---|---|---|
| M1 | **JAN読取 → 商品情報＋バッジ** | カメラ（@zxing/browser）・手入力・品名検索で商品を特定し、事実データ（①）と、成分×通知ルール（②）から導いたバッジを数秒で出す。バッジ例：リスク区分／指定濫用防止の対象（根拠成分）／運転注意（眠気等）／授乳中は服用しない or 相談／15歳未満・12歳未満は服用しない／カフェイン（1回量）／ドーピング禁止表の掲載成分（年版）。各バッジをタップすると根拠（通知の該当項目と記載条件、または成分と分量）を表示 |
| M2 | **複数品の比較（2〜4品）** | 基準をそろえた成分・分量の表で、違う行だけ1色で強調。バッジの違いも並べる。量の多い順などの並べ替えで優劣を示さない。値タップで出典 |
| M3 | **質問エージェント（出典つき回答）** | 「授乳中は？」「眠くなる成分は？」「何歳から？」などの自然文に、役割分担のエージェントが答える：①質問の解釈 → ②商品事実の検索 → ③通知ルールの照合・該当箇所の抜き出し → ④出典の検証（出典のない文は捨てる）→ ⑤禁止語ガード。回答は**該当箇所の抜き出し＋出典**で、要約・言い換えはしない。根拠が見つからなければ「該当する記載が見つかりません。添付文書（PMDA）で確認してください」 |
| M4 | **逆引き・成分検索** | 自由入力（例「鼻水」「眠くならないかぜ薬」「カフェインが入っていないもの」）を、Claude が承認基準の効能・効果の語と成分条件に対応づけ、該当する商品を**順位なし・同列**で出す。各商品に一致した根拠（効能・効果の範囲の該当語、成分の有無）を付ける。入力は保存しない。「この中から選ぶのは販売者です」を表示 |
| M5 | **棚の位置を分かりやすく表示** | 店内マップ（架空1店舗）で売場・棚番をハイライトし、棚の正面図で段と左右の位置を示す。複数品を選んでいれば全部を同時に示す |
| M6 | **出典・HITL・ガード** | すべての表示に出典。「判断は販売者が行ってください」を全画面で常時表示。Claude が生成した文はすべて禁止語ガード（正規表現＋Claude自己検査）を通し、引っかかれば差し止めてログに残す |

### P1（P0 が動いてから。順に着手）
| # | 機能 | 受け入れ基準 |
|---|---|---|
| M7 | **指定濫用防止の確認・記録＋販売記録の下書き** | 対象商品を読むと、通知（医薬発1226第16号 第4-1(4) ア〜キ）の順に確認項目を出す。個数から「複数」、内容量から「大容量」を表示。タップで確認済み、判定ボタンなし。Claude が販売記録の下書きを作り（ガード経由）、保存は商品・個数・確認項目・時刻・担当（仮名）のみ |
| M8 | **「相談すること」確認リスト＋困ったときの行き先** | 商品の成分から、通知の「相談すること」に当たる項目（妊娠・授乳、治療中、高齢者、持病など）を、お客様に聞く確認リストとして出す。症状が重い・続くときの一般的な行き先（医療機関、救急安心センター #7119 等）を常に示す。個人の受診要否は判定しない |
| M9 | **ベテランの説明メモ共有** | 商品・成分・薬効群ごとに、ベテランが「聞かれたらここを確認する」「この欄を見せる」などの説明ポイントを残せる。新人は商品を読むと関連メモが出る。メモもガードを通し、推奨表現は差し止め |

## 7. User Stories
- **US1 一目で分かる**：登販として、お客様が持ってきた箱の JAN を読むだけで、指定濫用防止・眠気・授乳・年齢・カフェイン・ドーピングに関わる成分がバッジで分かり、根拠もすぐ見たい。
- **US2 比べる**：「これとこれ、何が違う？」と聞かれたら、2〜4品を読んで、違うところだけを数秒で示したい。
- **US3 聞かれたことに根拠で答える**：「授乳中でも飲める？」と聞かれたら、通知のどの項目に何と書かれているかをすぐ出して、自分の言葉で伝えたい。判断は自分がする。
- **US4 逆引き**：「鼻水に使えるもので、眠くならないものある？」と聞かれたら、条件に合う商品を順位なしで出し、どれを案内するかは自分で決めたい。
- **US5 棚へ案内**：案内すると決めた商品が店のどこにあるかを、マップと棚の図ですぐ示したい。
- **US6 確認と記録**：指定濫用防止の商品を複数買うお客様に、通知の順で漏れなく確認し、確認した事実を記録したい。
- **US7 受け継ぐ**：ベテランとして、説明のコツを商品ごとに残し、新人が同じ水準で説明できるようにしたい。

## 8. Success Metrics
**必須KPI：推薦ゼロ**（全出力を禁止語リスト＋人手で検査し、おすすめ・順位付け・効き目の比較・販売可否の判定が0件）

| 指標（デモ用） | 目標 |
|---|---|
| JAN読取 → バッジ表示 | 3秒以内 |
| 質問 → 出典つき回答 | 15秒以内 |
| バッジの正しさ（通知ルールの導出 vs ゆうが実物の添付文書で確認した結果） | デモ商品で測定して提示（目標【仮】95%以上） |
| 出典のない回答 | 0件（出典検証で捨てた件数もログで見せる） |
| Claude なし版との比較 | キーワード検索だけでは答えられない質問（記載条件の当てはめ、効能語への対応づけ）で差を示す |
| 新人とベテランの回答の一致 | デモ後・現場で測定（P2） |

## 9. Constraints / Compliance
- **BWC 作成禁止例**：「医療アドバイスを行うAI」「基本的なRAGアプリケーション」。
  - 医療アドバイス：使うのは登録販売者で、AIは個人の状態を判定しない。回答は公的通知の抜き出しと出典で、判断は人（HITL）。
  - 基本的なRAG：通知の記載条件を構造化ルールにして商品の成分に当てはめる推論、役割分担のエージェント、出典検証、ガードで、単なる検索＋生成と区別する。
- **運営確認**：Discord で Kai（HITL がないものが禁止事例。該当しなければルール上OK）と岡本先生の注意6点を取得済み。逆引きを含む今回の設計も問題ないことをゆうが確認済み（2026-11-02）。
- **行政確認**：都道府県の薬務課に、逆引き・バッジ・質問回答の設計が医療機器（プログラム）や広告規制に当たらないかを先に確認する（T000）。回答は memory.md に記録。
- **岡本先生の注意6点との対応**：①個人の病気を判断させない → 判定なし、入力は保存しない ②「診断できる」等を書かない → uiCopy と README を検査 ③推さない → 順位なし・推薦ゼロKPI ④最終判断は人 → 常時表示・判定ボタンなし ⑤健康情報 → 保存しない・模擬のみ ⑥根拠と行き先 → 全表示に出典、M8 で行き先。
- **薬機法上の判断は登販**。販売可否の判定はしない。
- 認証なし（ハッカソン期間）。

## 10. Out of Scope（Won't）
おすすめ順・ランキング・「この人にはこれ」・PB優先・クーポン／効き目の強弱・スコア／用法用量の個人計算・年齢体重計算／併用可否・禁忌の個人判定・受診要否の判定／販売可否の自動判定・「売ってよい」ボタン／お客様の氏名・症状・健康状態・既往歴の保存／客向けモード・QR公開／商品固有の添付文書本文の表示・保存・再配布／実行時の PMDA 自動アクセス・クロール／他店の棚・在庫／POS連携。

※ v1.x で禁止していた「症状入力」は、v2.0 で「登録販売者による効能・効果の語の自由入力（保存しない・順位なし・承認基準の効能範囲との照合のみ）」として M4 に限り許可する（L-20261102-32）。お客様の症状の記録・個人の状態判定は引き続き禁止。
